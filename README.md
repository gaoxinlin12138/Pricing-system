# 星瀑花洒内部计价平台

一个面向公司内部的花洒组合计价 MVP。员工只能看到最终对外售价，管理员维护产品、配件和统一计价参数。

## 本地运行

### 一键启动（推荐）

直接双击项目根目录的 `启动项目.bat`（等价于 `py 启动.py`）。启动器会自动：

- 优先使用 `backend/.venv` 里已装好依赖的 Python，避免用到系统 Python；
- 读取根目录 `.env`；没有 `.env` 时提示输入 PostgreSQL 密码；
- 数据库 `pricing` 不存在时自动创建，并执行 Alembic 迁移；
- 首次运行时前端缺少 `node_modules` 会自动 `npm install`；
- 8001 / 5173 被其它程序占用时自动顺延到下一个空闲端口，并在窗口里打印实际地址。

窗口保持打开即为运行中，按 `Ctrl+C` 可以同时停止前后端。

想先看到完整流程，可以运行一次演示数据脚本（通过接口创建示例主体、配件和 3 个套装，随时可在后台删除）：

```powershell
backend\.venv\Scripts\python.exe scripts\seed_demo_data.py
```

脚本默认连接 `http://127.0.0.1:8001`；如果后端启动在其它端口，先设置 `PRICING_BASE_URL`，例如：

```powershell
$env:PRICING_BASE_URL="http://127.0.0.1:8002"
backend\.venv\Scripts\python.exe scripts\seed_demo_data.py
```

### 后端（开发模式）

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:app --reload --port 8001
```

端口 `8000`/`8001` 在本机可能已被其它程序占用，启动失败时换一个空闲端口即可。

### 前端

```powershell
cd frontend
npm install
npm run dev
```

打开 `http://localhost:5173`。

登录账号在首次启动（空库）时创建，由环境变量 `INITIAL_ADMIN_PASSWORD` / `INITIAL_EMPLOYEE_PASSWORD` 决定；本地不带这两个变量时会使用内置默认密码，生产部署务必在 `.env` 里显式设置（见 [DEPLOY.md](DEPLOY.md)）。

## Docker 部署

```powershell
docker compose up -d --build
```

打开 `http://localhost:8080`。生产环境应在 Nginx 或云负载均衡器前配置 HTTPS，并替换演示密码。

部署到阿里云 ECS 的完整步骤（安全组、Docker、Nginx、HTTPS、备份、更新）见 [DEPLOY.md](DEPLOY.md)。

Docker 部署使用 PostgreSQL，后端容器启动时执行 Alembic 迁移。正式环境请通过环境变量替换数据库密码、`SESSION_SECRET` 和 `COOKIE_SECURE`。

项目运行必须显式设置 `DATABASE_URL`；当前运行链路统一使用 PostgreSQL，不再自动回退到本地 SQLite 文件。测试会在测试环境中显式注入临时 SQLite 地址。

管理员后台包含概览（含报价趋势与账号入口）、计价参数、配件（主体已并入配件目录）、预设套装、账号、报价和审计日志页；员工端先搜索预设套装，再按同类别替换配件并保存报价快照。

配件类别字段已经内置到后台录入表单：主体、杆子、中叉+墙座、花洒喷头（手喷与顶喷已合并为同一类）、电话线、手喷软管、喷枪、弯角角盘。选择类别后会显示对应的颜色、长度、形状、材质、档位等字段；属性值以结构化 JSON 保存，不参与员工端成本展示。

数据库迁移：

```powershell
cd backend
$env:DATABASE_URL="postgresql+psycopg://pricing:pricing@localhost:5432/pricing"
alembic upgrade head
```

本机已安装 PostgreSQL 时，推荐使用脚本自动创建 `pricing` 数据库并迁移：

```powershell
.\scripts\setup_local_postgres.ps1
```

脚本会隐藏式读取密码，只在当前进程使用，不会写入项目文件。

以后可以直接在项目根目录编辑标准 `.env` 文件，把 `DATABASE_URL` 改成你的 PostgreSQL 连接地址，然后右键运行 `启动.py`（也可以双击 `启动项目.bat`）。例如：

```env
DATABASE_URL=postgresql+psycopg://postgres:你的密码@127.0.0.1:5432/pricing
```

脚本会自动迁移数据库并启动前后端，不再每次询问密码。`.env` 已在 `.gitignore` 中，不会被提交。

启动后访问 `http://127.0.0.1:5173/`（若端口被占用，以启动窗口打印的地址为准）。启动窗口保持打开，按 `Ctrl+C` 可以停止对应服务。

备份脚本位于 `scripts/backup_postgres.ps1`。正式环境请将 `SESSION_SECRET` 替换为随机长密钥。

## 数据与文件存放

- **业务数据**：全部在 PostgreSQL 的 `pricing` 库里（连接串见根目录 `.env`），表包括 `accessories`、`bundles`、`bundle_items`、`quotes`、`users`、`pricing_settings`、`audit_logs`；迁移前的旧表 `bodies` 仍保留作回滚备份，运行期不再读写。数据库文件由 PostgreSQL 自己管理（本机默认在 `E:\software\PostgreSQL\data`）。
- **图片**：只存本地文件，目录是 `backend/uploads/`（由 `UPLOAD_DIR` 决定），文件名随机（如 `CqlXU7HIq9-2mt29NisGCw.webp`）。数据库里只存 URL（`/uploads/xxx.webp` 或上传接口返回的完整地址），前端统一按同源 `/uploads/` 访问，开发时由 Vite 代理到后端。

删除规则：

- 主体、配件、套装、账号、报价都是**真实删除**（`DELETE`），没有软删除；
- 主体或配件仍被套装引用时，删除/停用会被拒绝；
- 删除记录时，它引用的本地图片只在**没有任何记录再引用**时才从磁盘删除（共享图片保留到最后一次引用）；
- 服务启动时会扫描 `backend/uploads/`，把没有被主体/配件/套装引用的孤儿文件清掉；
- 报价保存的是快照，删除套装不影响历史报价文本；快照里的套装封面 URL 会随文件删除失效（目前界面不展示该图，属于已知限制）；
- 审计日志不随业务删除清空，会标记「目标已删除」；需要彻底清空可调用 `DELETE /api/admin/audit-logs`。

## 使用流程

### 管理员

1. **概览**：查看配件、预设套装、报价和账号数量，以及近 14 天 / 6 个月 / 12 个月的报价趋势。
2. **配件**：左侧按类型导航、右侧展示该类型的完整信息（成本、数量范围、状态与属性），可整体查看或只看某一类。**主体也是其中一种类型**：录入名称、型号、成本、图片和描述即可，每套固定选一个；其余类型再补充属性与数量范围（杆子、花洒喷头、电话线……）。带单位的属性（长度、厚度/重量、尺寸大小、适配杆径等）只填数字会自动补上 mm/m；属性下拉旁的小 × 可以清空该项。属性只用于展示，不参与计价。
3. **套装**：自由选择「1 个主体 + 若干配件」组成预设套装，填写套装编号、上传一张**套装成品效果图**后保存，员工端即可搜索到。编辑器按配件类型各预置一行 BOM，「主体」也是其中一行且为必选；其余类型直接选对应配件即可，留空的行保存时自动跳过。成品图是员工端卡片和详情页的封面，没传图时显示占位图并在后台标记「缺图」，不会拿主体图顶替。
4. **计价参数**：统一维护倍率、人工费和报价有效期。

主体与配件共用一张表（类别为 `主体`），套装通过 `bundles.body_id` 引用主体记录；主体不参与同类别替换，也不能作为 BOM 配件重复加入。员工替换配件时只要求同类别。迁移 `0008` 会把原 `bodies` 记录复制到 `accessories`，并同步改写套装的 `body_id` 和历史报价快照；`0009` 补齐带单位属性，`0010` / `0011` 依次移除税率与折扣上限、最低售价，`0012` 移除运费。旧 `bodies` 表保留作回滚备份，运行期不再读写。

套装只保存对主体/配件的**引用**（`bundle_items` 里只有 `accessory_id`、数量和排序），不复制名称和成本。所以之后修改配件的名称、型号、类别、属性、图片或成本，所有引用它的套装会立即跟着变（售价按新成本重算）；已经保存的报价仍是保存当时的快照，不受影响。被套装引用的配件不能删除，也不能停用。

### 员工

1. 搜索预设套装 → 点击进入，先看到套装成品图，下面是 **BOM 式物料明细**：第一行是主体（固定，不可替换），其余是配件。
2. 需要换配件时点「替换」，从同类别配件中选择；也可以调整数量，或点「恢复」回到原配件。
3. 调到满意后点右侧「确认报价」进入第三步，这时才计算并显示单套售价；在第三步调整「套装套数」，实时查看多套总价。未确认前步骤条 03 不可直接进入，返回第二步或修改配件/数量后需要重新确认（成本明细不对员工展示，BOM 里同样不显示单价；第二步不试算，避免员工通过反复替换反推单件成本）。
4. 确认后保存报价单：保存的是当时的物料组合快照（含套装编号、套数和总价），**不会修改原预设套装**；历史报价也不受后续调价影响。

## 计价规则

```text
配件总成本 = Σ（单件配件成本 × 各配件数量）
成本小计 = 主体成本 + 配件总成本 + 统一人工费
单套售价 = 成本小计 × 统一倍率
多套总价 = 单套售价 × 套装套数
```

金额在后端使用 Decimal 计算并在最后保留两位小数。报价保存时写入价格快照，因此价格调整不会影响历史报价。

## 视觉规范

- 米白 `#FCF9E8`（RGB 255 249 232，CMYK 2-3-12-0）：页面背景
- 星光蓝 `#41BBC8`（RGB 65 187 200，CMYK 67-8-27-0）：品牌色，用于主按钮、步骤选中态、表头底色与图标；浅色版 `#E4F4F6` 用作标签、表头和强调区块背景
- 星光蓝明度较高，实心按钮与选中态上使用深墨色文字 `#07383E`（对比度约 5.6:1），不使用白字
- 中性色偏暖（边框 `#E7E1CF`、次要文字 `#64756F`），与米白背景统一

样式令牌集中定义在 `frontend/src/style.css` 顶部的 `:root`，改品牌色只需改这几个变量。

## 删除与历史记录

主体、配件、套装、账号和报价均执行真实删除。主体或配件仍被套装引用时，删除/停用会被阻止；删除套装会级联删除套装明细。历史报价继续使用保存时的快照，即使原套装后来被删除也不影响查看。账号删除后，报价和审计日志保留用户名快照，用户外键置空。审计日志会把已删除的业务目标明确标记为“目标已删除”。当前登录账号和系统中的最后一个管理员不能删除。
